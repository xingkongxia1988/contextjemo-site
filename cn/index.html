01 / 可沉淀

语义沉淀下来

战术是文件，不是聊天记录。它落在 git 里，像代码一样 diff、 像代码一样回滚。同事不用问你，就能读到 Agent 被交代了什么、 以及为什么。

#CHARTER-03.7
02 / 可复制

语义被复制出去

一个战术，很多 Agent 用。同一份声明式文件，可以驱动不同模型、 不同平台。改好一次打法，所有使用者一起继承这次改进—— 改进不需要再解释一遍。

#BRIEF-1.3
03 / AI 化

语义层自己长出 AI

语义层不是静态文档。Agent 读它、照它执行、再写回它： update_kernel 让内核随运行进化， 跨模型核验为结果把关。这一层因为被使用而变好， 而不是因为有人维护 wiki。

#SPEC-1.0

02 · 两种文件

两份产物。
都是纯文本。

ContextJemo 里的一切都是提示词，只是结构分三层： 内核装的是绝不能变的东西，AET 战术装的是要做什么， 提示词模板是最小的可复用单元。

内核 · MD

价值观与红线

≤ 90 行硬预算。公理、自我认知、红线各归其位。 超预算校验器直接拒绝——注意力是稀缺资源，克制本身就是能力。

#CHARTER-03.3
AET · YAML

步骤与验收

1–20 步。每一步都是自然语言指令，配一条可机判的验收标准。 你声明「什么算完成」，运行时决定怎么做到。

#SPEC-2.1
kernel.md — 五段结构，≤90 行 
### 四、红线规则（Bottom Line）

| 红线 | 触发动作 |
|------|---------|
| R1：无来源结论 | 结论不写入报告，改为「待核」标注 |
| R2：营销内容当事实 | 降级为「参考」，注明来源性质 |
| R3：超出知识截止日期 | 标注「数据可能过时」 |
| R4：单一来源支撑关键结论 | 强制要求第二来源印证 |
| R5：预算超支（>80%）| 停止深度检索

03 · 我们的立场

黑盒让你「相信」它，
声明式让你「看见」它。

主流 Agent 编排是黑盒：你把任务丢进去，它内部怎么调度、灌了多少词、 烧了多少 token、每一步产出什么——全都看不见。ContextJemo 走相反的一条路。

维度黑盒 Agent 编排ContextJemo 声明式编排
调度逻辑藏在引擎里，不可见AET YAML 白纸黑字——你定义调谁、按什么顺序
每一步产出不可见每步产出可见、成本可见
经验沉淀在哪散在聊天记录里在 git 里——可 diff、可分享、可复利
掌控权交给引擎握在你手里——改 YAML 就改行为
迭代方式等厂商升级自己迭代——改一处跑一次立刻见效
哪一步崩了不知道checkpoint 机判，一目了然
#VALUE-02 可预期，才是资产的前提。
04 · 生命周期

说 → 成 → 试 → 用 → 长

One Paper：一份打法的完整一生，从一句话意图，到能复利的资产。 Demo 不是弃子，是打法的燃料——资产是被这些燃料淬炼出来的。

01

说

一句话描述成果。不追问、不做需求三连问。

02

成

共创大脑直接出草稿，待确认项在文件内标注，你改哪句点哪句。

03

试

试演产出可见、成本可见——缺输入时诚实标注，禁止编造。

04

用

打法落盘为 YAML 入库——可版本化、可分享、任何 Agent 都能跑。

05

长

运行数据与人工确认回灌资产，每次被确认的运行都让它更准。

#CHARTER-04 确认即资产：确认了什么、依据什么、拍板什么、结果如何、谁签的字。
